# Ren2Leaf

将 Ren'Py 作品迁移至 [NarraLeaf Studio](https://www.narraleaf.com) 的前置工具。本工具在本机读取一份 Ren'Py 工程，产出一份交给 Agent 的**迁移补充包**：补充包不替代源码，而是补上源码里读不出来的那部分。

迁移本身由 Agent 依据配套 Skill 在 Studio 中完成。本工具不改写剧本、不生成 NarraLeaf 代码、不触碰原工程。

## 本工具解决的问题

把 Ren'Py 工程连同源码直接交给 Agent，Agent 能读到语句，读不到两类信息：

- **只有运行时才成立的事实。** 一个界面最终呈现成什么样，是 `screens.rpy` 的布局语句、`gui.rpy` 的变量、样式继承与运行期求值共同作用的结果。按代码反推元素的位置与尺寸，误差足以让移植后的界面失真。
- **本应由作者来定的设计决定。** 哪些 `Character` 变量是独立角色，哪些只是同一个人的别名或不需要建档的过场人物；剧本按什么边界分章。这取决于作品自身的结构与作者意图，静态扫描无从判定。

Ren2Leaf 对这两类信息分别处理：前者在 Ren'Py SDK 中运行游戏副本，按实际画面取图并记录元素坐标；后者在界面上交由迁移者逐项确认。两者连同静态扫描的结果，一并写成一份 Markdown 文档与若干数据文件。

因此交给 Agent 的是**证据与决定**，而非推测。补充包中的每一张表都标明该行出自何处：迁移者（人已确认）、扫描（静态读出的事实）、引擎（截图时自运行中的游戏取得）。

## 环境要求

| 项 | 说明 |
| --- | --- |
| Node.js | ≥ 20 |
| Ren'Py SDK | 仅「截图」步骤需要。在 `/Applications`、`~/Applications`、`~`、`~/Desktop` 及 `~/.ren2leaf/sdk` 下按 `renpy-<版本>-sdk` 自动识别，亦可手动指定路径 |
| 操作系统 | macOS 为主要验证平台。截图步骤的沙箱策略（`sandbox-exec`）与「在 Finder 中显示」为 macOS 专有，其余功能不依赖平台 |

无需安装依赖，仓库不引入任何第三方运行时包。

## 启动

```bash
npm start
```

服务默认监听 `http://127.0.0.1:4710` 并自动打开浏览器。可用参数：`--port <端口>`、`--no-open`。

服务仅绑定回环地址；Host 不属于本机的请求一律拒绝（防 DNS 重绑定），写操作必须携带 JSON 请求体。

在界面中通过「添加游戏」登记工程路径，可填写工程根目录、其 `game/` 目录，或 macOS 的 `.app` 包。

## 迁移流程

侧栏的五个步骤对应补充包的五类内容。「诊断」须至少运行一次，否则无从导出；每个步骤均可标记为「不写入补充包，由 Agent 自行判断」，对应各节会写明该项留给 Agent，而不是留下空白。

### ① 诊断

静态扫描 `game/` 下的全部脚本，产出一份清单（`inventory`）：游戏规格与建议 SDK、界面与调用点、`Character` 定义、Python 语句与变量、label 图与菜单结构、文本标签与转场、素材引用与缺失。扫描只陈述事实，不作判断，也不代替迁移者决定任何事。

对不符合 Ren'Py 开发规范的写法，已知情形已做兼容；其余情形可能解析异常，异常本身会被标注出来，交由 Agent 复核。

### ② 截图

本步骤是唯一执行游戏代码的环节，须先确认信任该工程，确认状态按工程保存且可撤销。运行方式：

- 运行的是工作目录中 `game/` 的副本，原目录不参与运行；
- 存档与 persistent 数据写入工作目录（`RENPY_PATH_TO_SAVES`），可选择性地复制一份现有存档进去，用于从进度中段取图；
- macOS 下默认置于 `sandbox-exec` 沙箱：断开对外网络，仅允许写入工作目录与系统临时目录；
- 运行结束后比对原目录指纹，若原目录在运行期间发生变化，界面会明确告警。

游戏照常游玩，在需要迁移的画面上按 **F9** 取图。每次取图保存整图、元素表（类型、内容、位置、样式与源码位置），并可在图上圈选切图、填写该画面的用途说明。本工具不自动遍历画面：取哪些画面，由迁移者在游玩过程中自行决定。

未截图但已被扫描识别到的界面会单独列出，以便确认是遗漏还是无需迁移。

### ③ 说话人

逐个确认 `Character` 变量的身份：主要角色、POV 角色、NPC / 别名、临时角色，或从名单中移除。扫描提供的只是证据——台词数量占比、配音取号的连号关系、立绘 tag、首次出现位置——分类由迁移者点选。

别名的判定依据是配音取号的连号关系，而非目录名。有配音的说话人必须成为角色（配音只能挂在已存在的角色上），因此别名在补充包中亦作为独立角色列出。

### ④ 流程与章节

Studio 的层级为**故事 → 章节 → 场景**：整部作品是一个故事，剧本文件对应章节，文件内的 label 对应场景。本步骤由迁移者指定章节分组与拆分方式（不拆分 / 按选项拆分 / 全拆分），并排除非剧本文件。

扫描提供游玩顺序、可达性、菜单与选项去向、结局判定，以及疑似章节分界信号（黑场、停止音乐、过场视频、成就点）；分界线划在哪里由迁移者决定。

### ⑤ 导出补充包

将以上内容写成一个文件夹。请将该文件夹连同游戏源码一并交给 Agent。

截图在写出时会无损重压缩：引擎给出的 PNG 未经逐行滤波，体积接近原始像素缓冲，重写后像素逐字节一致，体积通常降至三分之一。

## 补充包的内容

```
<游戏名>-ren2leaf/
├── README.md                          交给 Agent 的迁移文档，入口
├── screens/<界面>.png                 截图，以及圈选出的切图
├── characters/<变量>.png              角色立绘或对话截图
└── data/
    ├── inventory.json                 完整扫描结果
    ├── screens/<界面>.elements.json    该界面的元素坐标
    ├── speakers.json                  迁移者确认过的说话人身份
    └── chapters.json                  迁移者定的章节分组
```

`README.md` 是写给 Agent 读的，开篇即要求其先更新 Skills，并声明「本文件是路牌，不是方案」：文档只陈述原作事实与迁移者决定，具体如何落地由 Agent 判断。文档中被截断的长表，均可在 `data/inventory.json` 中取得全量。

## 实例：The Question

[`examples/The-Question-ren2leaf/`](examples/The-Question-ren2leaf/README.md) 是一份真实产出的补充包，取材自 Ren'Py SDK 自带的示例作品 The Question（`<SDK>/the_question`，1280×720，单剧本文件，两处选项分支、两个结局）。

该实例中迁移者所作的决定如下：

| 项 | 决定 |
| --- | --- |
| 说话人 `s` | 主要角色 Sylvie，全篇唯一有立绘的角色 |
| 说话人 `m` | POV 角色 Me，玩家视角的叙述者，原作未给专名 |
| 章节 | 单章「第一章」，收 `script.rpy` |
| 拆分方式 | 按选项拆分：选项引出的支线各自成为独立场景 |

截图一步取了 10 张画面（主界面、设置、关于、帮助、读取游戏、保存、历史、游戏界面、选项、对话框），共 528 处元素坐标，覆盖源码中 22 个界面里的 12 个；未截到的 10 个界面在第 6 节逐个列出，并附各自的 action，以便判断是遗漏还是无需迁移。

阅读这份文档即可了解补充包的体例：事实与决定如何分列、哪些结论标了出处、哪些事项被明确声明为「本工具没有检查」。

## 工作目录

```
~/.ren2leaf/
├── games.json            已登记的工程（含备份，异常清空时自动恢复）
└── work/<id>/            每个工程的工作目录：扫描结果、截图、迁移者的决定、导出产物
```

可用环境变量 `REN2LEAF_HOME` 改写位置。工具从不写入游戏自身的目录。

截图与运行副本占用空间较大，可在工程菜单中按组清理；清理项会列出各组体积与清理后将失去的内容。

## 配套 Skill

迁移前请先安装 NarraLeaf Skills：

```bash
npx skills add NarraLeaf/Skills -g
```

Ren'Py 移植 Skill 随本工具发布，位于 `skills/narraleaf-port-renpy/`，请一并提供给 Agent。Agent 接入 Studio 的相关事宜参见 <https://www.narraleaf.com/zh/docs/studio/agent>。

## 已知限制

- 迁移本身不依赖本工具：即使工程未遵循 Ren'Py 开发规范、以致扫描出现异常，Agent 仍可依据源码完成迁移。在非标准写法上出问题的是扫描这一环，而非移植本身。
- `.rpa` 归档与仅存字节码的 `.rpyc` 不作解包，其中的脚本与界面不在补充包内。
- 素材只核对存在性、格式与重复，不读取内容：图像尺寸与透明边、音频时长与响度、视频帧率均不在检查范围。
- ATL 动画只统计用在何处，不解析其内容。
- 一个立绘 tag 下仅差属性的多条定义，具体哪一行用哪一条，须运行时方可确定。

补充包的第 9 节逐项列出了本工具没有检查的内容，Agent 不应将该节之外的任何一节视为「已确认无误」。
