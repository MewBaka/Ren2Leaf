# Ren2Leaf

Ren'Py 作品迁移至 [NarraLeaf Studio](https://www.narraleaf.com) 的前置分析工具。本工具于本地读取 Ren'Py 工程，输出一份交给 Agent 的**迁移补充包**——它不替代源码，而是补全静态分析无法获取的那部分信息。

实际的迁移工作由 Agent 依据配套 Skill 在 Studio 中完成。本工具不修改剧本、不生成 NarraLeaf 代码、不触碰原工程目录。

## 设计动因

将 Ren'Py 工程连同源码直接交给 Agent，Agent 能读取语句，却无法获取两类关键信息：

**运行时才成立的事实。** 一个界面的最终呈现，是 `screens.rpy` 的布局语句、`gui.rpy` 的变量定义、样式继承与运行期求值共同作用的结果。仅凭代码反推元素的位置与尺寸，误差足以让移植后的界面失真。

**需要作者裁定的设计决策。** 哪些 `Character` 变量是独立角色，哪些只是同一角色的别名或无需建档的过场人物；剧本应按什么边界划分章节——这些取决于作品自身的结构与作者意图，静态扫描无从判定。

Ren2Leaf 对这两类信息分别处理：前者在 Ren'Py SDK 中运行游戏副本，按实际画面取图并记录元素坐标；后者在界面上交由迁移者逐项确认。两者连同静态扫描的结果，一并写成一份 Markdown 文档与若干数据文件。

因此交给 Agent 的是**证据与决定**，而非推测。补充包中的每一张表都标明该行信息的出处：迁移者（人工确认）、扫描（静态读出）、引擎（运行时取得）。

## 环境要求

| 项 | 说明 |
| --- | --- |
| Node.js | ≥ 20 |
| Ren'Py SDK | 仅「截图」步骤需要。在 `/Applications`、`~/Applications`、`~`、`~/Desktop` 及 `~/.ren2leaf/sdk` 下按 `renpy-<版本>-sdk` 自动识别，亦可手动指定路径 |
| 操作系统 | macOS 为主要验证平台。「截图」步骤的沙箱策略（`sandbox-exec`）与「在 Finder 中显示」为 macOS 专有，其余功能不依赖特定平台 |

无需安装依赖，本仓库不引入任何第三方运行时包。

## 启动

```bash
npm start
```

服务默认监听 `http://127.0.0.1:4710` 并自动打开浏览器。可用参数：`--port <端口>`、`--no-open`。

服务仅绑定回环地址，Host 不属于本机的请求一律拒绝（防 DNS 重绑定），写操作必须携带 JSON 请求体。

在界面中通过「添加游戏」登记工程路径，可填写工程根目录、其 `game/` 目录，或 macOS 的 `.app` 包。

## 补充包的内容

```
<游戏名>-ren2leaf/
├── README.md                          交给 Agent 的迁移文档，入口
├── screens/<界面>.png                 截图，以及圈选出的切图
├── characters/<变量>.png              角色立绘或对话截图
└── data/
    ├── inventory.json                 完整扫描结果
    ├── screens/<界面>.elements.json    该界面的元素坐标
    ├── speakers.json                  迁移者确认过的说话人身份
    └── chapters.json                  迁移者指定的章节分组
```

`README.md` 是写给 Agent 读的，开篇即要求其先更新 Skills，并声明「本文件是路牌，不是方案」：文档只陈述原作事实与迁移者决定，具体如何落地由 Agent 判断。文档中被截断的长表，均可在 `data/inventory.json` 中取得全量。

## 实例：The Question

[`examples/The-Question-ren2leaf/`](examples/The-Question-ren2leaf/README.md) 是一份真实产出的补充包，取材自 Ren'Py SDK 自带的示例作品 The Question（`<SDK>/the_question`，1280×720，单剧本文件，两处选项分支、两个结局）。

该实例中迁移者所作的决定如下：

| 项 | 决定 |
| --- | --- |
| 说话人 `s` | 主要角色 Sylvie，全篇唯一有立绘的角色 |
| 说话人 `m` | POV 角色 Me，玩家视角的叙述者，原作未给专名 |
| 章节 | 单章「第一章」，收 `script.rpy` |
| 拆分方式 | 按选项拆分：选项引出的支线各自成为独立场景 |

截图一步取了 10 张画面（主界面、设置、关于、帮助、读取游戏、保存、历史、游戏界面、选项、对话框），共 528 处元素坐标，覆盖源码中 22 个界面里的 12 个；未截到的 10 个界面在第 6 节逐个列出，并附各自的 action，以便判断是遗漏还是无需迁移。

阅读这份文档即可了解补充包的体例：事实与决定如何分列、哪些结论标了出处、哪些事项被明确声明为「本工具没有检查」。

## 工作目录

```
~/.ren2leaf/
├── games.json            已登记的工程（含备份，异常清空时自动恢复）
└── work/<id>/            每个工程的工作目录：扫描结果、截图、迁移者的决定、导出产物
```

可用环境变量 `REN2LEAF_HOME` 改写位置。工具从不写入游戏自身的目录。

截图与运行副本占用空间较大，可在工程菜单中按组清理；清理项会列出各组体积与清理后将失去的内容。

## 配套 Skill

迁移前请先安装 NarraLeaf Skills：

```bash
npx skills add NarraLeaf/Skills -g
```

Ren'Py 移植 Skill 随本工具发布，位于 `skills/narraleaf-port-renpy/`，请一并提供给 Agent。Agent 接入 Studio 的相关事宜参见 <https://www.narraleaf.com/zh/docs/studio/agent>。

## 发给 Agent 的提示词

补充包生成后，与源码一并交给 Agent，并以下文作为任务说明。其中三处占位需要替换：`{游戏名称}`、`{源代码文件夹}`、`{Ren2Leaf生成的文件夹}`。

````markdown
# 任务：将 Ren'Py 游戏《{游戏名称}》完整迁移到 NarraLeaf Studio

## 背景与输入
- `{源代码文件夹}`：原 Ren'Py 游戏源代码文件夹，作为唯一参照，只读，不要修改。
- `{Ren2Leaf生成的文件夹}`：迁移文档，包含本次迁移的约定、图片、注意事项和已知问题。
- 请调用 NarraLeaf 相关技能完成迁移。

## 第一步：开始前必须完成的阅读
1. 完整阅读 `{Ren2Leaf生成的文件夹}` 下的全部文档。文档中的约定辅助于你的默认做法。
2. 阅读 NarraLeaf 相关技能的说明，确认可用的 API、组件和项目结构。
3. 通读 `{源代码文件夹}` 的 `.rpy` 脚本、`screens.rpy`、`options.rpy`、`gui.rpy` 及资源目录。

完成后先输出一份**功能清单**再动手迁移。清单逐项列出原游戏的所有功能并标注迁移方案，至少覆盖以下内容：
- 剧情脚本（label、jump、call、menu 分支）
- 变量与条件判断（含 persistent 持久化变量）
- 角色定义、立绘、表情切换
- 背景、CG
- 转场与动画效果（transform、ATL）
- BGM、音效、语音
- 自定义 screen 与 UI：标题、存读档、设置、历史记录、快进、自动播放、隐藏对话框
- 多结局与 CG 鉴赏、回想等解锁系统
- 文本样式与特殊标签
- 原生 Python 逻辑

## 第二步：迁移
- 按功能清单逐项迁移，保持剧情文本、分支逻辑、演出时序与原版一致。
- NarraLeaf 没有现成对应功能的，要自行设计实现，在行为上对齐原版。不得删除、跳过该功能，不得留空壳、TODO 或占位实现。
- 资源文件全部迁移并正确引用，不得出现缺图、缺音频或路径错误。
- 遇到迁移文档未覆盖、且确实需要用户决定的问题，先暂停并说明选项。能自行合理判断的问题，直接做出选择并记录理由。

## 第三步：验收标准（“迁移完成即上线”）
交付前逐项自检，全部满足才算完成：
1. 项目可在 NarraLeaf Studio 中无报错地构建和运行。
2. 从标题界面开始，每条分支、每个结局都能完整走通，无死路、无断档。
3. 存档、读档、设置、历史记录、快进、自动播放等系统功能均可正常使用，存档在重启后依然有效。
4. 功能清单中的每一项都标记为“已实现”，并注明对应的实现位置。
5. 所有资源均被正确加载，控制台无缺失资源警告。

## 第四步：交付迁移报告
迁移完成后，输出一份迁移报告，包含以下内容：
1. **概述**：迁移范围、最终项目结构、运行方式。
2. **功能对照表**：原 Ren'Py 功能 → NarraLeaf 实现方式 → 状态。
3. **自研实现说明**：NarraLeaf 无原生支持、由你自行实现的功能，说明设计思路与所在文件。
4. **与原版的差异**：任何行为、表现上的偏差及原因。如无差异，明确写“无”。
5. **验收结果**：第三步各项的自检结果，以及分支、结局的测试覆盖情况。
6. **已知问题与后续建议**：如有，按严重程度排序。
````

## 已知限制

- 迁移本身不依赖本工具：即使工程未遵循 Ren'Py 开发规范、以致扫描出现异常，Agent 仍可依据源码完成迁移。在非标准写法上出问题的是扫描这一环，而非移植本身。
- `.rpa` 归档与仅存字节码的 `.rpyc` 不作解包，其中的脚本与界面不在补充包内。
- 素材只核对存在性、格式与重复，不读取内容：图像尺寸与透明边、音频时长与响度、视频帧率均不在检查范围。
- ATL 动画只统计用在何处，不解析其内容。
- 一个立绘 tag 下仅差属性的多条定义，具体哪一行用哪一条，须运行时方可确定。

补充包的第 9 节逐项列出了本工具没有检查的内容，Agent 不应将该节之外的任何一节视为「已确认无误」。
